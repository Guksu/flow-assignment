# 팀 규칙

이 파일은 팀 소유이며 업데이트가 덮어쓰지 않는다. `.agents/harness-core-rules.md`보다 우선한다.

코드에서 알 수 없는 팀 결정만 적는다: 브랜치 관례, 검증 명령과 환경, 업로드·배포 조건, 기록 요구 여부. 기본값으로 충분한 항목은 생략한다.

기록·인계 양식은 선택 기능이다. 기록을 요구하려면 대상 작업과 위치를 여기에 명시한다.

## 팀 정책 (guksu-harness compose가 생성)

이 구간은 `.agents/harness-team.json`에서 만들어진다. 정책을 바꾸려면 `npx guksu-harness compose --set <키>=<값>`을 쓴다. 이 구간 밖은 팀이 자유롭게 쓴다.

### 작업 규칙
- 따라야 할 별도 지침 문서는 없다. 이 문서가 팀 규칙이다.
- 작업 브랜치: `feat/` `fix/` `refactor/` `docs/` 접두어를 쓰고 기준 브랜치 `main`에서 갈라진다. (추정 — 관례가 없어 기본값)
- AI의 작업 범위: 요청 범위의 구현과 결과 확인까지. 커밋·푸시는 요청이 있을 때만 한다. PR·머지는 요청이 없으면 하지 않는다. 민감정보 값은 읽지 않는다.

### 변경 보호
- 보호 브랜치: `main`. 이 브랜치 위에서는 파일을 편집하지 않는다(branchGuard 훅이 차단). (팀 확정 — 팀 결정 (compose --set))
- 커밋·푸시: 요청 시 허용(blockGitMutation 훅). force push·amend·rebase·reset·checkout은 항상 차단. (팀 확정 — 팀 결정 (compose --set))
- AI 작성 표기 차단: 켬. (팀 확정 — 팀 결정 (compose --set))

### 검증
- 완료 조건: 실행할 검증 명령이 정해지지 않았다. 요청 범위가 충족됐는지 확인하고, 실행한 검사와 하지 않은 검사를 밝힌다. (팀 확정 — 팀 결정 (compose --set))
- 종료 검사 훅(verifierGate): 사용 안 함 — 규칙으로만 요구한다. (저장소 근거 — 검증 명령이 없어 훅으로 강제할 것이 없다)

### 기록·인계
- 작업 기록: PR마다 `docs/history/` 기록 한 건을 남긴다(기록 없는 push는 훅이 차단). (팀 확정 — 팀 결정 (compose --set))

미확인 항목: 없음.

## 이 저장소의 결정 (2026-10-21)

위 생성 구간과 겹치면 이 절이 우선한다.

- 설계 단일 출처: `docs/design/2026-10-21-file-extension-policy.md` (4단계 완성 전까지 작성 중). 단계별 분석은 `docs/analysis/`
- 브랜치·PR: main 보호. 기능 단위 브랜치(`feat/`·`fix/`·`test/`·`docs/`·`chore/`) → PR(베이스 main) → 사용자 리뷰 후 머지. **PR 생성까지는 이 과제의 상시 요청**이고 머지는 사용자가 한다
- 커밋: `feat:`/`fix:`/`docs:`/`test:`/`chore:` + 한국어 제목, 본문은 글머리표. PR 본문: `## 개요` / `## 주요 변경`(커밋 해시) / `## 확인한 것`(실행한 명령과 결과) / `## 참고`(확인 못 한 것), 합니다체. Claude 작성자 표기·워터마크 금지
- 사전 확인: GitHub 저장소 생성, 배포 실행, 환경 변수 등록은 실행 전에 사용자에게 확인받는다
- 공개: 퍼블릭 배포 필수(과제 S2). 저장소는 public으로 유지한다(설계 문서 문답 #8 — 과제 원문은 "GitHub 주소"만 요구하지만 평가자 계정 없이 열려야 함)
- 비밀값: DB 접속 정보 등은 `.env.local`에 두고 AI는 읽지 않는다. 필요한 키 이름만 `.env.example`에 적는다
- 구현: TDD(red → green). 확장자 파싱·정규화와 정책 판정은 순수 함수로 분리해 서버에서 강제한다(파일 시그니처 판정은 하지 않기로 함 — 설계 문서 문답 #5). 클라이언트 검증은 UX 용도
- 기록:
  - PR마다 `docs/history/{YYYY-MM-DD}-{브랜치 요약}.md` (history 양식)
  - 세션마다 `docs/history/{YYYY-MM-DD}-session-{n}.md` — 그 세션의 진행·결정·남은 일
  - `PROMPT_LOG.md`는 단계·PR이 끝날 때마다 추가. AskUserQuestion 선택은 "제시된 선택지 / 내 선택 / 이유"로
  - 사용자가 잡은 AI 오류는 설계 문서 "AI 오류 노트"에 즉시 기록. 사용자가 기록하지 말라고 한 내용은 어떤 문서·커밋에도 남기지 않는다
  - 공개 저장소에 올리기 전에 다른 회사·개인 정보가 들어가지 않았는지 확인한다
- 검증 명령: 앱 뼈대 PR에서 확정한 뒤 `compose --set verification.checks=...`로 연결한다
