시작 프롬프트의 기준은 **"면접 당일 누구나 바로 열 수 있는가"**다. 세부 항목은 잠들기, 일시 중지, 만료, 요청 크기 제한, 휘발성 디스크. 문답 #7에 따라 **1달 이상 방치해도** 버텨야 한다.

2단계에서 넘어온 조건도 함께 본다.

**Neon 세부 사항**

- **지역**: 서울·도쿄 지역이 없다. 아시아·태평양은 싱가포르(`aws-ap-southeast-1`)와 시드니뿐이다. DB는 싱가포르에 두고, Vercel 함수 지역과 Blob 스토어 지역도 싱가포르로 맞춰 왕복을 줄인다. Blob 스토어 지역은 만든 뒤 바꿀 수 없다. Hobby에서 함수 지역을 바꿀 수 있는지는 앱 뼈대 PR에서 실제로 확인한다(점검표 A5).
- **연결 (위험 O4)** — 4단계에서 `pg` + Neon 풀링 연결로 바꿨다(문답 #18, 설계 문서 2.5). 아래는 3단계 당시 검토 내용: 서버리스 드라이버는 TCP 대신 HTTP나 WebSocket으로 접속해 서버리스 환경에 맞는다. HTTP의 `transaction()`은 여러 쿼리를 한 트랜잭션으로 보내지만 중간 결과를 보고 분기하는 대화형 트랜잭션은 아니다. 대화형이 필요하면 WebSocket `Pool`/`Client`를 쓴다.
- **200개 제한의 잠금 (위험 P5)**: HTTP `transaction()`으로도 된다. 첫 문장에서 트랜잭션 범위 advisory lock을 잡고, 둘째 문장에서 "200개 미만일 때만 INSERT"를 하면 된다. READ COMMITTED는 문장마다 새 스냅샷을 보므로, 잠금을 기다린 뒤의 INSERT는 먼저 끝난 트랜잭션의 행을 본다. 방식 확정과 동시 요청 테스트는 4단계·구현에서 한다.
- **5분 뒤 연산 0**: 비활성 뒤 첫 쿼리는 연산이 깨어나는 시간만큼 늦다. 면접 직전에 한 번 열어 깨운다(8장).

**업로드 경로 (위험 U7)**: **서버 경유**를 추천한다.

- 서버 경유는 판정·저장·메타데이터 기록이 한 요청 안에 있다. 로컬에서도 같은 방식으로 돈다. 대신 파일 크기가 함수 본문 상한(4.5MB)에 묶인다.
- 직접 업로드(Blob 클라이언트 업로드)는 4.5MB를 넘길 수 있다. 하지만 Vercel 문서는 토큰 발급 전에 사용자를 인증하라고 하고, 인증 없이는 누구나 스토어에 올릴 수 있다고 경고한다. 우리는 인증이 없어서 발급 전 판정과 요청 제한만이 문이 된다. 완료 콜백(`onUploadCompleted`)은 로컬에서 동작하지 않아 터널이 필요하다.
- 이 과제의 시연 파일은 몇 MB면 충분하다. 크기 상한을 플랫폼 상한 아래로 두는 쪽이 단순하다.

| Blob 고급 작업 2,000회 소진 → 업로드 30일 정지 | 하루 총량 상한으로 막는다. 상한에 닿으면 그날 업로드만 거부하고 정책 관리는 계속된다 | [구현] | D4, D6 |
| Neon 저장 1GB 초과 → 쓰기·삭제 실패 | 파일을 DB에 넣지 않아 위험이 크게 줄었다. 이력·요청 제한 행은 정리한다 | [구현] | P13, U9 |
| Neon 연산 시간 소진 → 다음 달까지 정지 | 남용이 길게 이어질 때만. 감시로 먼저 안다 | [문서로만] + 감시 | D6, D10 |
| 첫 요청 지연 | Neon은 5분 무요청 뒤 첫 쿼리가 늦다. DB가 싱가포르라 한국에서 왕복이 있다 | [문서로만] + 면접 직전 예열 | D10 |
| 예약 감시 중단 | 공개 저장소 60일 무활동이면 꺼진다. 면접이 두 달 넘게 뒤라면 그 전에 저장소에 활동을 남긴다 | [문서로만] | D10 |
| 짧은 로그 보관 | Hobby 실행 로그는 1시간만 남는다. 지난 사고를 로그로 되짚기 어렵다 | [문서로만] — 정책 변경은 감사 테이블(P7)에 남으므로 핵심 기록은 DB에 있다 | O2 |
| 직접 업로드 미사용 | 파일 상한이 4.5MB 아래로 묶인다 | [문서로만] — 시연에 충분, 운영이라면 클라이언트 업로드 + 발급 전 판정 | U2, U7 |

## 8. 면접 당일 점검과 플랜 B

- **전날**: 상태 감시 기록 확인, 배포 URL에서 정책 변경 → 업로드 차단·허용을 한 번씩 해 본다
- **30분 전**: URL을 열어 함수와 DB를 깨운다. 필요하면 "기본값으로 초기화"
- **오늘 저장 수 (위험 D4)**: 하루 50건이 차면 KST 자정까지 정상 파일 업로드가 막히고, 정책 초기화로는 풀리지 않는다. Neon 콘솔에서 `SELECT count(*) FROM upload_attempt WHERE status = 'stored' AND created_at >= date_trunc('day', now() AT TIME ZONE 'Asia/Seoul') AT TIME ZONE 'Asia/Seoul'`로 확인한다. 막혔을 때는 ① 차단 시연(실행 파일 업로드)은 그대로 된다 ② 정상 업로드는 로컬 실행(플랜 B)으로 보인다 ③ 꼭 배포에서 보여야 하면 오늘 저장된 행의 `expires_at`을 `now()`로 바꾸고 정리 크론을 `CRON_SECRET`으로 한 번 호출해 파일과 행을 지운다(Blob 작업 수를 쓰므로 한 번만)
- **플랜 B**: Vercel이 한도 소진으로 멈췄다면, 저장소를 로컬에서 실행해 화면을 공유한다(README의 실행 방법 그대로 — 위험 G7). 이를 위해 로컬 실행이 배포용 DB 없이도 되게 한다(로컬 Postgres 또는 Neon 개발용 브랜치) — 4단계에서 정함
