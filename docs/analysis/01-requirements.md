## 6. 애매한 부분 — 질문 목록 (Q)

사용자가 정해야 하는 것만 모았다. "언제"는 그 답이 필요한 단계다. 1단계 질문은 AskUserQuestion으로 바로 묻는다.

| Q1 | `file.exe.txt`에서 무엇을 확장자로 보나 | (a) 마지막 확장자만 → `txt` · (b) 점으로 나눈 뒷부분 전부 → `exe`, `txt` · (c) 마지막 확장자 + 점 포함 커스텀 항목(`tar.gz`)은 끝부분 일치 | **(c)**. (b)는 캡처 파일명에 흔한 `naver.com.png`를 고정 확장자 `com` 때문에 막는다. 내용이 실제 실행 파일인 `file.exe.txt`는 Q4의 내용 검사가 잡는다 (→ Q4에서 내용 검사를 하지 않기로 해서, 이 경우는 이름대로 `txt`로 보고 통과시킨다. 비공개 저장·다운로드 없음이라 실행될 경로가 없다) | 1단계 |

**확정 (2026-10-21)** — 자세한 내용은 설계 문서 2장 결정 표와 5장 문답 기록 #1~#7.

- Q1: (c) 마지막 확장자 + 복합 항목. 단, 사용자가 복합 규칙을 더 조이라고 해서 **점 경계에서 정확히 일치, 각 단 `[a-z0-9]+`, 최대 2단**으로 정했다(AI 오류 E1). 포함 관계(`gz`와 `tar.gz`가 함께 있는 경우)는 막지 않는다.
- Q2: (a) 마지막 점 뒤를 확장자로 본다.
- Q3: (a) 거부하고 고정 쪽으로 안내한다.
- Q4: 논의 끝에 **확장자 정책만 구현하고 내용 검사는 문서로만** 남긴다. 추천 (c)는 버렸다(AI 오류 E2). 그래서 기본값 D7의 "내용 검사는 그대로 적용"도 없어진다.
- Q5: (a) 비공개 저장 + 메타데이터만 표시.
- Q6: 모름 → 1달 이상 방치해도 버티는 구성을 3단계 기준으로.
- Q7: (a) 인증 없이 공개 + 기본값 초기화 + 변경 이력 (2단계 문답 #10).

## 8. 실측 근거

질문 Q2와 기본값 D1·D2의 근거로 Node.js 22.12 `path.extname`의 동작을 직접 확인했다.

| 입력 | `path.extname` 결과 | 순진하게 쓰면 |
| --- | --- | --- |
| `.env` | `""` | 확장자 없음 |
| `.exe` | `""` | `exe` 차단을 통과 |
| `file.exe.txt` | `".txt"` | 마지막만 본다 |
| `file.PDF` | `".PDF"` | 소문자 변환 필요 |
| `a.tar.gz` | `".gz"` | 복합 확장자 인식 불가 |
| `evil.exe.` | `"."` | `exe` 차단을 통과 |
| `evil.exe ` | `".exe "` | `exe` 차단을 통과 |
| `naver.com.png` | `".png"` | 마지막만 보면 정상 |
| `ｅｖｉｌ.ｅｘｅ` (전각) | `".ｅｘｅ"` | NFKC 없이는 `exe`와 다름 |

Python `os.path.splitext`도 `.env`·`.exe`를 확장자 없음으로 본다. 그래서 파싱은 표준 함수를 그대로 쓰지 않고, 이 표를 테스트 케이스로 삼아 직접 작성한다.
