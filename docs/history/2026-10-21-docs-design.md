## 1. 개요

설계 문서를 정본으로 완성했다. 이제 구현은 이 문서를 따른다. 문서에는 결정 표, 판정 규칙의 입력→출력 표, 테이블 스키마 5개(트리거 포함), 주요 흐름, API, 테스트 전략, PR 순서가 들어 있다. 결정 9건은 사용자와 한 질문씩 정했다(문답 #17~#25).

주요 변경은 세 가지다.
- DB 접근을 3단계의 Neon 서버리스 드라이버에서 `pg` + 풀링 연결로 바꿨다.
- 정책 테이블은 재검토 끝에 고정·커스텀 두 테이블로 정했다.
- 사람별 요청 제한은 이번 범위에서 뺐다.

## 2. 작업 내용

**범위 재조정 (PR #4를 올린 뒤)**: 사용자가 별도 세션의 Claude로 평가자 관점 중간 점검을 받아 "범위가 커지고 복잡도가 높아진다"고 판단했다. 마감(10-22)을 정하고, [구현] 76개를 필수 요구·판정 규칙 핵심·나머지로 나눈 뒤 6개를 내리거나 단순화했고(문답 #26~#30), D8은 영향 검토 끝에 문서로만으로 내렸다. 결과는 설계 문서 2.6(범위에서 뺀 것), 11장(PR 5개), 위험 표 숫자(구현 73 · 문서로만 13 · 제외 7), AI 오류 E13·E14, 점검표 A11·A12.

## 4. 확인 필요 · 후속

- 사용자가 설계 문서를 리뷰하고 머지한다. 머지되면 이 문서가 정본이다
- PR 5(1일차 배포): Neon 프로젝트·Vercel 프로젝트·Blob 스토어 생성과 환경 변수 등록을 **한 번에 묶어** 사용자에게 확인받는다(사용자: "환경설정은 빠르게 묶어서 가자")
- 점검의 할 일 3~7: 선택 기록 이유를 사용자에게 묻기(#4·#8·#10·#13·#14·#16·#23·#29·#30), PROMPT_LOG에서 AI가 추정한 의도 목록 뽑기, 회고 재료 정리, 원문 추출·제출 문서
- 설계 14장 "배포 뒤 확인할 것"을 PR 5·9·10에서 처리한다

## 5. 주의사항

- 위 DDL·동시성 확인은 일회성 스크립트였다. PR 7에서 같은 경우를 Vitest 통합 테스트로 옮긴다
- 풀러(PgBouncer)를 거칠 때의 잠금 동작은 로컬에서 확인할 수 없어 배포 뒤 확인한다(설계 14장)
- 4단계 문답 시각은 대략값이다. 정확한 시각은 대화 원문 추출 때 확인한다
