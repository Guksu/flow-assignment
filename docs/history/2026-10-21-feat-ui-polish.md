## 1. 개요

제 요청 "지금 UI를 과제 제출용으로 깔끔하게 만들어줘 -> suta 스킬을 사용해."로 화면을 다듬었습니다. 시작 전에 화면 구성·말투·글꼴과 색·추가 개선 네 가지를 물어 정했습니다(문답 #41). 동작과 API는 바꾸지 않았고, 화면 문구만 해요체로 바꿨습니다.

## 2. 작업 내용

| 파일 | 하는 일 |
|------|------|
| `src/app/page.tsx` | 머리(제목·한 줄 설명) → 두 패널 → GitHub 링크. 넓은 화면(960px 이상)은 정책 왼쪽·업로드 오른쪽, 좁은 화면은 한 열 |
| `src/app/policy-panel.tsx` | 첫 조회 중 스켈레톤, 실패하면 오류와 "다시 시도". "기본값으로 초기화"는 브라우저 기본 확인창 대신 "취소 / 초기화" 확인 창. 추가 버튼은 저장하는 동안 진행 표시. 성공 안내는 화면 읽기 프로그램에만, 오류는 그 자리에 빨간 글자 |
| `src/app/upload-panel.tsx` | 끌어다 놓는 영역(누르면 파일 고르기), 둘 이상 놓으면 고르지 않고 이유를 알림. "올리기"가 화면의 유일한 채운 버튼. 결과 상태는 색 알약 대신 색 글자 |
| `src/app/globals.css` | 값은 토큰에서만 고름. 흰 패널 + 옅은 회색 바탕, 패널은 테두리·그림자 없음. 동작 줄이기 대응 |
| `src/app/layout.tsx` | Pretendard(SIL OFL 1.1) 분할 글꼴을 불러옴 |
| `src/ui/**` | suta 패턴 코드 복사: 토큰 두 벌, 확인 창(`Modal`), 진행 버튼(`LoadingButton`), 스켈레톤, 끌어다 놓기 코어 |
| `src/domain/messages.ts` | 화면·API 문구를 해요체로. 차단 문구는 "고정 확장자 exe에 걸려 업로드할 수 없어요."처럼 한 문장으로 |

새 의존성: `pretendard` 1.3.9(SIL OFL 1.1).

복사한 suta 코드 두 곳(`Modal.tsx`, `useAsyncAction.ts`)은 이 프로젝트의 린트 규칙(렌더 중 ref 쓰기 금지)에 걸려 고쳤습니다. 확인 창의 Esc 처리는 `useEffectEvent`로, 진행 버튼의 옵션 갱신은 effect 안으로 옮겼습니다.

## 4. 확인하며 고친 것

- 375px에서 커스텀 입력 줄이 패널 밖으로 25px 밀려 나갔습니다. 입력칸의 기본 폭이 그리드 열을 늘린 것이라, 패널과 묶음의 열을 `minmax(0, 1fr)`로 묶었습니다.
- 좁은 화면에서 "기본값으로 초기화"가 두 줄로 꺾이고 패널 설명이 버튼 옆에 좁게 끼었습니다. 머리를 "제목 | 버튼" 한 줄 + 설명 한 줄로 바꿨습니다.
- 차단 안내가 "…확장자예요: sh (커스텀 확장자) 올려 보면…"처럼 문장이 끊긴 채 이어졌습니다. 차단 문구를 한 문장으로 바꾸고 테스트로 고정했습니다.
