> ## 무엇이 문제인가
>
> - 과제 4-1은 내가 입력한 텍스트, 그때의 의도, 다시 물은 방법을 보고 싶어 해. 지금 로그는 대부분 AI가 요약한 "요지"고, 실제 입력이 인용된 건 P4·P6·P9 정도야.
> - 과제 4-3은 내가 잡은 걸 강조하라고 하는데, 지금은 "AI가 스스로 잡은 것", "점검표를 실제로 적용했다" 같은 AI 성과가 굵은 제목으로 서 있어.
> - 1장에서 나를 "사용자"라고 18번 부르고, "나/내가"는 한 번뿐이야. 내가 제출하는 문서인데 AI가 나에 대해 쓴 보고서로 읽혀.
> - P3·P7·P8에는 "머지했어 N단계 진행해줘"만 남아 있어서, 진행해줘만 치고 AI가 다 한 것처럼 보여. 실제로는 작업 방식을 P0·P1에서 설계하고 단계 사이엔 승인만 한 건데, 그 설계가 P0 세 줄과 P1 요약 한 문단에 묻혀 있어.
> - 내가 방향을 바꾼 장면이 30행짜리 선택 기록 표 안에 묻혀 있어. 복합 확장자 더 조이기, 내용 검사의 법·정책 반론, 실무 로그 형태, Next.js 풀스택 이유, 다른 기업·확장성 재검토, 요청 제한 범위 제외 같은 것들.
> - 읽기 어렵게 만드는 신호가 많아. 1장에만 ID 참조가 약 90개, 굵은 글씨가 약 40개고, 꼼꼼함을 보여 주려는 숫자 나열, "(이유 확인 필요)" 같은 빈칸 4곳, 사소한 도구까지 넣은 도구 표가 있어.

>      - 자기 칭찬형 소제목

>    - D1·D2·P7을 지금 설계에 맞춰 줘. 이력은 언제·무엇을·어떻게 바꿨는지만 남기고, 누가는 기록하지 않는다. 인증·쿠키·IP가 모두 없어서이고, 이건 우리 결정이다. 운영이라면 관리자 계정 ID를 남긴다.
>    - 과제 3-2가 "누가 언제 무엇을 바꿨는지"를 묻는 항목이니까, 나중에 CONSIDERATIONS.md에서 이 답이 분명히 보이게 해 줘.
>    - 쿠키를 뺀 결정에 기대던 행이 더 있는지도 훑어봐 줘(점검표 A2).
> 2. 요청 번호를 로그·응답에 연결
>    - 지금 request_id는 이력 행에 저장되고, 서버 로그에는 오류일 때만 찍혀. 응답에는 번호가 없어서 방문자는 오류 번호를 알 수 없고, 성공한 변경은 로그가 없어서 이력의 번호로 찾을 게 없어.
>    - 모든 정책 API 응답에 X-Request-Id 헤더를 넣고, 오류 본문에도 requestId를 넣어 줘. 화면은 오류 문구 뒤에 오류 번호를 짧게 보여 줘.
>    - 정책을 바꿀 때마다 서버 로그를 한 줄 남겨 줘. 요청 번호, 행위, 확장자만 쓰고 IP나 다른 개인 정보는 남기지 마.
>    - 설계 문서와 위험 표의 로그·모니터링 항목에 "요청 번호로 화면·응답·서버 로그·이력을 잇는다"를 적고, 테스트도 붙여 줘.

>    (가) 회사·팀·채팅방마다 다른 정책
>    - 출발점:
